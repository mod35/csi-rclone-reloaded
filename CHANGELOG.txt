# CHANGELOG
1.7.0 (modes):
- FEATURE: implemented NodeStageVolume / NodeUnstageVolume, so a volume is now mounted ONCE per node and bind-mounted into each consuming pod. Previously every pod got its own `rclone mount` process, and because they all shared --cache-dir they each found the same "Dirty" VFS cache items and raced to upload them. That produced OneDrive `409 resourceModified` (eTag mismatch) storms in which files were repeatedly truncated to 0 bytes on the remote: 4 pods on one node generated ~6500 409s, upload retries reached try #50, and throughput collapsed from MB/s to ~60 KiB/s. One mount per node means one VFS cache and one uploader, so the race cannot occur.
- NodeGetCapabilities is now overridden to advertise STAGE_UNSTAGE_VOLUME. This is required, not cosmetic: csicommon's DefaultNodeServer (drivers v1.0.2) reports only RPC_UNKNOWN and that library has no AddNodeServiceCapabilities helper, so without the override the kubelet never calls NodeStageVolume and the driver silently keeps one mount per pod.
- Per-pod readOnly is now applied as a read-only BIND mount in NodePublishVolume rather than on the shared rclone mount, which must stay writable for the pods that write. (NodeStageVolumeRequest has no Readonly field because readOnly is a per-publish concept.)
- NodeStageVolume is idempotent and self-repairing: if the staging path is already a healthy mount it is a no-op, and if it is a DEAD mount (ENOTCONN - the state the node-plugin's postStart umount hook leaves behind) it is unmounted and re-staged instead of failing forever.
- The per-volume rclone config file is now keyed on the staging path and removed in NodeUnstageVolume, since it belongs to the shared mount. NodeUnpublishVolume still removes a config keyed on the pod target path, which is now only produced by the legacy path.
- COMPATIBILITY: if the kubelet does not supply a staging target path, NodePublishVolume falls back to the previous per-pod direct rclone mount and logs a warning, so behaviour is unchanged in that case.
- DEPENDENCY MODERNISATION: removed github.com/kubernetes-csi/drivers (csi-common). That module was archived upstream at v1.0.2 and has no successor, so it could never be updated - it pinned the build to the 2019 tree (k8s.io/kubernetes v1.13.2, client-go v10.0.0+incompatible, CSI spec v1.0.0, grpc v1.18.0). Its ~150 lines of gRPC bootstrap, identity and controller servers now live in pkg/rclone/server.go. Node/identity/controller servers embed the generated csi.UnimplementedXServer, so future CSI spec additions no longer break the build.
- Replaced k8s.io/kubernetes/pkg/util/mount with k8s.io/mount-utils, and k8s.io/kubernetes/pkg/volume/util.UnmountPath with mount.CleanupMountPoint. Importing k8s.io/kubernetes as a library is unsupported upstream and was the reason go.mod was a wall of 2019 pseudo-versions. Bumped CSI spec v1.0.0 -> v1.13.0, client-go/api/apimachinery -> v0.36.3, klog -> klog/v2, grpc -> v1.83.1, cobra -> v1.10.2, and dropped github.com/golang/glog.
- The k8s v0.36 libraries require go 1.26, so the go directive and the Dockerfile/Dockerfile.dm builder stage moved from 1.24 to 1.26-alpine.
- SECURITY: stopped logging whole CSI requests. `klog.Infof("...%+v", *req)` dumped VolumeContext, which carries `configData` - the rclone config including OneDrive OAuth access/refresh tokens and crypt passwords - into the node-plugin pod log. Individual non-secret fields are logged instead. (It also copied a sync.Mutex, which go vet flags now that the CSI protos embed protoimpl.MessageState.)
- Added test/kind: a disposable end-to-end harness that proves N pods sharing a volume produce exactly ONE rclone process, using rclone's :local: backend so it needs no cloud credentials.
- Bumped the pinned rclone v1.74.3 -> v1.75.0 (SHA256-verified per arch). v1.75.0 carries four VFS fixes that match failures seen in production on this stack: "fix crash when multiple mounts or servers share the same VFS" (exactly the pre-v1.7.0 configuration), "fix IO error by recreating the cache file if it has been removed" (matches the unexplained EINVAL `create cache file failed` / `open RW handle failed` errors), "fix invalid seek position when cache files larger than the remote" (cache file ~1GiB while the remote item was 0 bytes), and "fix vfs cache writeback timer not being stopped when --transfers reached".
- FIX (found by the kind harness, would have been worse than the old driver without it): NodePublishVolume now repairs a dead staging mount, not just NodeStageVolume. After the node plugin restarts, the rclone process dies and the staging path becomes an ENOTCONN endpoint, but the kubelet still records the volume as staged and calls NodePublishVolume ONLY - NodeStageVolume is never called again. The bind then failed with "transport endpoint is not connected" on every retry and new pods sat in ContainerCreating forever. Both RPCs now share one ensureStaged() helper.
- FIX: ensureStaged probes and clears a dead mount BEFORE any mkdir. os.MkdirAll stats the path first, and on a dead FUSE endpoint that stat returns ENOTCONN rather than "not a directory", so MkdirAll fell through to mkdir(2) and failed with EEXIST ("file exists") - making a dead staging mount unrecoverable.
- KNOWN LIMITATION: pods that were already RUNNING when the plugin restarted keep a dead bind mount and must be recreated. Their bind was taken against the old mount instance; re-mounting the source does not retroactively repair existing binds. The driver self-heals for NEW pods only - the rclone-mount-healer CronJob in the media-server repo covers the rest.
- DEPLOYMENT REQUIREMENT: the node-plugin DaemonSet must now mount /var/lib/kubelet/plugins/kubernetes.io/csi with Bidirectional propagation. CSI staging paths live there (not under /var/lib/kubelet/pods), so without it staging cannot work.

1.6.0 (modes):
- Pinned rclone to v1.74.3 in all Dockerfiles (was floating "latest stable" via install.sh, which has no version pin); online builds now do a per-arch, SHA256-verified direct download.
- Pinned the golang builder stage to golang:1.24-alpine (was untagged golang:alpine, which floated the toolchain).
- Reconciled cmd/csi-rclone-plugin/Dockerfile(.dm) with the root Dockerfiles: fuse3 (was fuse) and alpine:3.19 (was alpine:3.16), rclone v1.74.3.
- Removed dead driver defaults --cache-info-age=72h and --cache-chunk-clean-interval=15m (deprecated rclone "cache" backend, no-ops on VFS mounts).
- Removed the hardcoded --dir-cache-time=5s default; it now falls through to rclone's native 5m default (5s hammered OneDrive and widened the mkdir race behind 409s).
- BEHAVIOR CHANGE: CSI mountOptions (PV/StorageClass mountFlags) and readOnly are now honored (previously computed then discarded). A PVC mounted readOnly now passes --read-only to rclone, and PV/StorageClass mountOptions are emitted as rclone flags.
- The per-volume rclone config is now written to a deterministic path (0600) and removed in NodeUnpublishVolume, fixing the indefinite accumulation of plaintext-secret temp files (previously ioutil.TempFile was never cleaned up).
